# 一、private_send v0.3.2

`private_send` 是供本人 Windows 电脑和 iPhone 在同一可信局域网内使用的私有文字、图片与通用文件传输工具。Windows 运行本机 HTTP 服务，iPhone 通过 Safari 打开配对页面；消息历史和附件保存在 Windows 本机。

本说明对应 v0.3.2 的当前产品范围。服务仅使用 HTTP，不提供 TLS、互联网中继、账号体系或云端备份；请只在自己信任的局域网中使用。

## 二、安装与启动

### （一）运行条件

- Windows 10 或更新版本
- Python 3.11 或更新版本
- Windows 电脑与 iPhone 连接到同一个可信 Wi-Fi
- iPhone 使用 Safari

### （二）安装依赖

在项目目录打开 PowerShell：

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

### （三）启动服务

在项目根目录执行：

```powershell
.\.venv\Scripts\python.exe -m app.main
```

服务默认监听本机所有网络接口的 `9527` 端口，并尝试在 Windows 默认浏览器打开页面。电脑本机地址为 `http://127.0.0.1:9527/`；同一局域网设备使用启动时生成的私有 IPv4 地址访问，例如 `http://<局域网IPv4>:9527/`。尖括号内容是说明占位符，不是可直接使用的地址。

启动时会生成本次进程使用的临时配对凭证，并在页面提供二维码。二维码只用于将 iPhone 配对到当前服务；不要分享二维码、带凭证的完整链接或浏览器凭证。服务重启后需要使用新二维码重新建立会话。产品文档和示例只展示不含凭证的地址。

### （四）首次配对

1. 确认电脑与 iPhone 接入同一个可信 Wi-Fi。
2. 在 Windows 浏览器打开本机页面，等待配对二维码出现。
3. 使用 iPhone 相机扫描二维码，并在 Safari 中打开。
4. 在两个浏览器页面确认设备身份为 PC 或 iPhone；身份用于消息标记。
5. 分别发送一条短文字，确认两端页面都收到。

如果 Windows 防火墙询问是否允许访问，只允许专用网络，不要为公用网络开放端口。访客 Wi-Fi、客户端隔离或 VPN 可能阻断设备之间的连接。

## 三、发送文字、图片与文件

### （一）文字

在 Composer 输入文字并按 Send。空白文字会被拒绝；单条文字按 UTF-8 编码不得超过 64 KiB。文字消息写入本机 SQLite 历史。

### （二）图片和通用文件

先在 Composer 选择一张或多张图片、一个或多个文件。选择后，附件会先进入待发送队列，供你确认本批内容；按 Send 后队列才开始上传。每个附件依次显示 `READY`、`UPLOADING`、`PROCESSING`、`COMPLETED` 或 `FAILED` 状态和进度。失败项会保留在当前页面队列中，可单独 Retry 并回到 `READY`；已经成功的项目不会因重试失败项而重复发送。请保持页面打开，直至队列处理结束。

每个成功上传的附件作为单独的历史消息出现。图片支持 JPG/JPEG、PNG、GIF、WEBP、HEIC 和 HEIF，单张上限为 100 MiB。可预览的图片可在页面中查看，HEIC/HEIF 不转换，可能无法直接预览，但仍可下载。

通用文件不限定扩展名或 MIME 类型，单个文件上限为 512 MiB。文件按原始字节保存；PDF 可尝试在新页面打开，其他文件提供下载。文件卡片只是附件信息，不会在服务端执行文件内容。

图片与文件可多选并批量排队，但每个项目独立上传和记录。一个项目失败不回滚同批其他成功项目；检查失败提示后，可以只重试失败项目。刷新或关闭浏览器会结束当前页面会话，未完成队列不作为可靠的持久化任务继续执行。

### （三）历史、轮询与滚动

打开页面时先显示最近 50 条历史；服务每约两秒通过 HTTP 轮询发现新消息。收到新消息或发送成功后，消息区会自动滚动到最新内容。点击 Load Older 时，页面向前读取一页历史并保留当前阅读位置，不把视图跳回最新消息；需要更早记录时可重复点击。

消息删除会先要求确认。删除文字消息会从可见历史中移除该条记录；删除图片或文件消息时，若没有其他有效消息引用该附件，本地附件也会进入删除流程。

## 四、局域网与访问边界

服务使用 HTTP，监听 `0.0.0.0:9527`；`127.0.0.1` 地址只适用于 Windows 本机，iPhone 应使用同 Wi-Fi 上的局域网 IPv4 地址。服务启动时会自动探测局域网 IPv4 地址，并提供二维码以简化 iPhone 配对。

临时凭证只在运行时生成，二维码和首次配对链接会携带它。凭证用于轻量访问控制，不加密网络流量，也不能替代 TLS。不要将服务暴露到互联网、公共 Wi-Fi 或不可信设备可访问的网络。

## 五、本机数据与数据库升级

运行数据保存在项目目录下的 `data/`：SQLite 数据库位于 `data/private_send.db`，附件暂存于 `data/staging/`，已完成附件存于 `data/assets/YYYY/MM/DD/`。数据库保存消息、文件元数据、摘要和相对路径；图片与文件二进制不放进 SQLite。日志（如启用）也属于本机数据，不应提交到版本库。

当前数据库路径为 `data/private_send.db`。首次启动时，如果只找到旧路径 `data/rainier.db`，程序会将数据库文件改名到新路径；附件文件夹不移动，数据库中的相对附件路径继续有效。如果新旧两个数据库文件同时存在，程序使用 `private_send.db` 并保留 `rainier.db`，不会合并两边的数据。升级前请停止服务，并自行备份整个 `data/` 目录。v0.2 的数据库会在数据库文件内事务性升级到 schema `user_version` 3：重建消息表以允许 `file` 类型，同时保留现有消息标识、内容、状态、时间和附件关系；已存附件文件不会改名或复制。重复启动时不会重复执行该表结构迁移。

新数据库也会直接建立为 schema 3。服务启动时会清理暂存区中超过 24 小时的普通 `.partial` 文件；近期文件或清理失败的文件会保留并等待后续清理。已提交为待删除的附件会在启动时重试删除。

## 六、发布验收清单

以下全部完成后才可将 v0.3.2 作为可发布版本。自动化检查通过不能替代 iPhone Safari 的人工验收。

- [ ] Windows 上依照本文档安装依赖并启动服务。
- [ ] 本机页面、二维码配对及重新启动后的重新配对正常。
- [ ] 在真实 iPhone Safari 上通过 HTTP 局域网地址完成连接；此项人工验证必需。
- [ ] PC 与 iPhone 双向发送文字、支持图片和通用文件；历史重新载入后仍存在。
- [ ] 多附件先在 Composer 待发送，再按 Send 开始；单项失败可独立重试且成功项不重复。
- [ ] 新消息自动滚动到底部；Load Older 保持历史阅读位置。
- [ ] 图片预览/下载、文件下载、PDF 打开及删除确认符合预期。
- [ ] 旧数据库迁移后保留文字、图片记录和附件；schema `user_version` 为 3。
- [ ] 防火墙只对专用网络开放，且服务未对公共网络或互联网开放。

## 七、版本边界

v0.3.2 支持文字、图片和通用文件。分块与断点续传、多用户、互联网中继、云端存储、原生移动应用、WebSocket 实时推送、自动图片格式转换和跨设备自动发现不属于当前版本承诺；后续版本须单独评估并明确发布范围。
