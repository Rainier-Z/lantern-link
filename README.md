# 一、private_send 1.0

`private_send` 是供个人 Windows 电脑与同一可信局域网内的 iPhone 传送文字、图片和文件的本机工具。Windows 上运行 HTTP 服务，iPhone 使用 Safari 配对并访问。数据保存在运行程序的 Windows 电脑上；本产品不提供云端存储、账号服务或公网中继。

## 二、安装与启动

### （一）运行条件

- Windows 10 或更新版本
- Python 3.11 或更新版本
- Windows 电脑与 iPhone 连接到同一可信 Wi-Fi
- iPhone 使用 Safari

### （二）创建环境并安装依赖

在项目目录打开 PowerShell，执行：

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

### （三）启动

在项目根目录执行：

```powershell
.\.venv\Scripts\python.exe -m app.main
```

服务默认使用 `9527` 端口，并尝试打开 Windows 本机页面。iPhone 应使用启动页面提供的同一 Wi-Fi 局域网地址和配对二维码。

## 三、配对与传送

### （一）配对 iPhone

1. 确认电脑和 iPhone 接入同一可信 Wi-Fi。
2. 在 Windows 浏览器打开本机页面，等待配对二维码出现。
3. 使用 iPhone 相机扫描二维码，并在 Safari 中打开。
4. 在各页面选择 PC 或 iPhone 作为设备标记，然后发送一条短文字确认连接。

每次服务启动都会生成新的临时配对凭证。不要分享二维码、配对链接或凭证。凭证只提供轻量访问控制，HTTP 不会加密网络流量。不要将服务开放到互联网或公共 Wi-Fi；Windows 防火墙只应允许可信专用网络访问。

### （二）发送文字

在输入框编辑文字并按 Send。空白内容会被拒绝，单条文字上限为 64 KiB。文字消息及其时间、发送设备标记会保存在本机历史中。

### （三）发送图片和文件

界面只有一个 File 选择入口。选择后可将多项内容加入待发送队列，再按 Send 开始逐项上传。服务根据内容的图片类型或通用文件类型分类；图片仍属于 File 入口中的一种附件分类。每个成功项目各自成为一条历史消息，某项失败时可单独重试，不会自动重复已成功项目。

图片支持 JPG/JPEG、PNG、GIF、WEBP、HEIC 和 HEIF，单张上限 100 MiB。HEIC/HEIF 会原样保存，浏览器不支持时仍可下载。通用文件不限制扩展名或 MIME 类型，单个上限 512 MiB；PDF 可尝试在新页面打开，其他文件提供下载。服务端不会执行上传的文件内容。

请保持页面打开，直到当前队列完成。刷新或关闭页面会结束当前队列会话，未完成项目不会作为可靠任务在后台继续。

## 四、历史与本机归档

消息历史和附件元数据保存在本机 SQLite 数据库中，图片和文件的二进制内容保存在文件系统，不写入数据库。右上角的 History 会打开按日期或文件分组的附件历史，可按类型筛选和搜索文件名。历史记录与附件是否仍在磁盘上分别管理：如果用户在程序外移除了已登记附件，记录仍会保留并标记为 `MISSING`；访问该附件会返回不可用响应。

上传成功的图片和文件归档在 Windows 用户 Downloads 下的 `file_private_send/YYYY-MM-DD/`，文件名尽量保留原名，冲突时添加编号。上传会先登记可恢复的待归档状态，再发布完整副本；若中断，下一次启动会继续该已登记操作。程序不会自动清理已归档的 Downloads 文件。未完成上传使用单独的暂存目录；启动时只清理超过 24 小时的普通 `.partial` 暂存文件。

私有运行数据使用 `%LOCALAPPDATA%/private_send/`：数据库为 `private_send.db`，上传暂存区为 `staging/`。应用默认把日志输出交给 Python 进程日志配置，不单独创建或轮转日志文件；若部署时启用持久文件日志，应放在该私有目录下的 `logs/`。路径使用环境变量形式展示，不包含本机账户名。

首次启动新版本时，如果检测到项目目录 `data/` 中的旧数据库或附件，程序会把缺少的内容安全复制到新位置，再初始化运行数据。数据库和附件迁移均保留原项目 `data/` 源文件；程序不会自动删除旧目录。首次升级前仍建议自行备份数据库和附件。

## 五、版本与范围

本应用版本为 1.0，运行时构建标识取当前 Git 提交的短 SHA；在 Git 信息不可用或格式无效时显示 `unknown`。数据库 schema 版本独立维护，当前为 3。

v1.0 提供单机本地存储、文字与文件传送、消息历史、图片/文件分类、日期归档及缺失附件标记。云端服务、公网中继、账号、多用户、TLS、原生移动端、分块续传及跨设备同步均不属于当前实现。v0.4 仅是未来路线图，相关能力尚未实现，也不是 v1.0 的发布承诺。
