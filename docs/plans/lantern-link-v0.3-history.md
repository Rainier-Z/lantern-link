# 一、Lantern Link v0.3 历史记录

本文归档 v0.3 系列曾提供的功能与数据约定，供升级和维护时理解历史记录。它不是当前部署指南；当前产品行为以根目录的 `README.md` 和 `TECHNICAL_PLAN.md` 为准。v0.4 仅为未来路线图。

## 二、v0.3 系列功能

v0.3 系列将文字、图片和通用文件保存为消息及附件元数据，使用 SQLite 维护历史，并将附件字节保存在本机文件系统。客户端提供单项上传队列、失败项重试、历史分页和增量轮询。服务面向同一可信局域网内的浏览器，使用 HTTP 和每次进程启动时生成的临时配对凭证。

旧版本使用项目 `data/` 作为运行数据根目录，数据库和暂存文件位于该目录，附件曾保存在 `assets/` 子目录。该路径只用于说明遗留结构，不表示 1.0 仍将新附件写入项目目录。

## 三、v1.0 的数据迁移关系

### （一）复制项目数据

v1.0 在 `%LOCALAPPDATA%/lantern_link/` 中初始化私有数据库和上传暂存区。首次启动时若检测到旧 `private_send` 数据或旧项目 `data/`，程序会把目标缺失的普通数据复制过去；数据库从旧文件复制，不会改写源文件。若新旧数据库并存，已有的目标数据库优先使用，不合并数据库。

### （二）导入遗留附件

旧资产文件会复制到 Downloads 归档根目录下的兼容位置，再按资产记录中的创建日期导入 `lantern_link/YYYY-MM-DD/`。成功复制后更新资产相对路径和存储文件名。旧项目源文件保留；程序不会自动删除旧 `data/` 内容或已归档 Downloads 文件。

### （三）保留历史和缺失状态

历史消息与附件元数据保存在 SQLite，附件字节保存在文件系统。文件不存在时，历史记录不会因缺失而删除；资产状态更新为 `MISSING`，下载返回 `410`。`MISSING` 是资产可用状态，不代表相应消息记录已被删除。

## 四、当前产品边界

当前界面使用单一 File 选择入口，并在内部把附件归为图片或通用文件。正常归档位置按日期分目录，路径显示为 `%USERPROFILE%/Downloads/lantern_link/YYYY-MM-DD/`。附件不会自动清理，过期上传暂存文件与已归档文件属于不同生命周期。

云端同步、账号、公网中继、多用户、TLS、分块续传和原生客户端不属于 v1.0。v0.4 及以后如需引入这些能力，应单独评估并形成明确实现和验收要求；本历史记录不构成对未来功能的承诺。
